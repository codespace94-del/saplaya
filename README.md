# Saplaya

One premium storefront for customers. Behind it, every product and order carries a `supplier_id`, so each independent farm tracks its own stock and orders in an admin panel.

```
saplaya/
├─ App.tsx                    splash → tabs
├─ src/                       React Native (Expo, TypeScript)
├─ backend/                   Node.js + Express (deploy to Railway)
└─ supabase/schema.sql        tables, RLS, triggers, realtime
```

## App name and icon
- The app display name is configured by `expo.name` in `app.json` (`Saplaya`).
- No custom icon artwork is configured yet. The current Android launcher icon is the generated placeholder in `android/app/src/main/res/mipmap-*/ic_launcher.webp` and `ic_launcher_round.webp`. These files are regenerated by Expo, so don't use them as the source for your custom icon.
- For a persistent custom icon, add a 1024 × 1024 PNG at `assets/icon.png`, then set `"icon": "./assets/icon.png"` in `app.json`. For Android adaptive icons, add a transparent foreground PNG at `assets/adaptive-icon.png` and configure `android.adaptiveIcon.foregroundImage` plus `android.adaptiveIcon.backgroundColor` in `app.json`. Expo uses these source files to generate the platform launcher icons.

## 1. Supabase
1. Create a project and run `supabase/schema.sql` in the SQL editor.
2. Run `supabase/mobile_account_payments.sql` after the base schema. It creates customer profile/address/review storage, supplier applications, avatar storage, and the paid-checkout records and RPC.
3. Auth → Providers → enable **Anonymous sign-ins** for guest sessions and **Email** for customer accounts. Customers can optionally upgrade a guest session or create an account with email and password.
4. Insert products (each with a `supplier_id`) and rows in `promos`. Use hosted high-resolution photos for `image_url`.
5. For a farm login: create the user in Auth, then set `suppliers.admin_user_id` to that user's id.

## 2. Backend (Railway)
```
cd backend && cp .env.example .env   # fill in SUPABASE_URL + SERVICE_ROLE key
npm install && npm run dev
```
Set `FLUTTERWAVE_SECRET_KEY` to a Flutterwave test secret during development and set `PUBLIC_API_URL` to the publicly reachable backend URL. Set `PAYMENT_APP_CALLBACK_URL` to `saplaya://payment-callback` when using the native app scheme. On Railway set the same variables; build `npm run build`, start `npm start`. The service-role key and Flutterwave secret live only on the backend.

Supplier admin endpoints (Bearer token of the farm's login):
- `GET /admin/orders`
- `PATCH /admin/supplier-orders/:id/status` with `{ "status": "packing" }`
- `GET /admin/inventory-movements`
- `POST /admin/restock`

## 3. App
```
cp .env.example .env     # set EXPO_PUBLIC_SUPABASE_URL, EXPO_PUBLIC_SUPABASE_ANON_KEY, EXPO_PUBLIC_API_URL
npm install
npx expo start
```
For Android builds with `npx expo run:android`, install JDK 17 and the Android SDK, and make sure `JAVA_HOME` points to JDK 17. Newer bundled JDKs can cause Android native dependency configuration to fail.

The home screen opens delivery-location editing and account management. The basket continues to checkout, where the backend recalculates the total before Flutterwave opens. An order is only created after the backend verifies a successful payment. Tracking includes order items and sideways-browsable order history.

Checkout requires the Supabase migration above, a reachable backend, and valid Flutterwave test credentials. The app scheme is `saplaya`; rebuild the native app after changing app configuration so the Flutterwave callback deep link is registered. Without payment settings, the app can still browse sample produce, but it will not simulate a payment or create a demo order.

## How the "secret supplier" design works
- Customers read `storefront_products` (a view without `supplier_id`). The app's types have no supplier fields.
- The mobile account migration revokes direct client execution of the legacy `place_order()` RPC. The backend verifies Flutterwave, then creates the order using the server-priced checkout snapshot in one transaction; the captured amount and recorded order total must match.
- When a farm changes its `supplier_orders.status`, a trigger recomputes `orders.status` (the least advanced farm wins; cancelled farms are ignored). Supabase Realtime delivers that UPDATE to the Tracking screen, and the four nodes glow in 🟡🔵🟣🟢.
- Cancelling returns stock and logs a `cancel_return` movement.

## Notes
- Product photos in `src/data/mock.ts` are Unsplash placeholders for demo mode; replace with your own.
- Delivery tiers (free ≤ 5 km, TSh 2,000 ≤ 10 km, TSh 4,000 beyond) live in `backend/src/index.ts` and `src/lib/delivery.ts`; the backend is authoritative.
- Profile pictures use the `customer-avatars` storage bucket created by the mobile account migration.
- Use Flutterwave test mode until the full payment callback and server verification flow has been tested in the target deployment.
